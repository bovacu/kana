kana — build commands
=====================

THE SOURCES (docs/architecture.md says what each layer is for):
  fude/drawing/   the drawing core, every app's: app/ (the shell's parts) base/ ink/ widgets/
  fude/study/     a study app's: app/ (its extension, verbs, files, flags) chars/
                  handwriting/ models/ screens/ widgets/ services/
  fude/lang/ja/   Japanese's own; fude/lang/zh/ Chinese's, fude/lang/ko/ Korean's (lang.h:
                  what a language gives)
  apps/kana/      Kana: kana.c (what it is, for the study shell: fude/study/app/shell.h),
                  kana.rdeproj (its build), src/ (version.h, text_ids.h), assets/,
                  platform/ios/, platform/android/, tools/, docs/, site/
  apps/hanzi/     Hanzi, Kana for Chinese: hanzi.c, hanzi.rdeproj, src/, assets/, platform/, tools/
  apps/hangul/    Hangul, Kana for Korean: hangul.c, hangul.rdeproj, src/, assets/, platform/, tools/
  tools/          the apps' shared tools: strings/, mlkit/, lectures/ (the
                  phrasebooks), icons/
  apps/draw/      Draw, the drawing app: draw.c, draw.rdeproj, src/, assets/, tools/
Each header is beside its source and is included by its layer's path
("drawing/widgets/row.h", "study/app/study.h"); the include paths are
-I<project>/fude and the app's src/. A source added to a layer's folder is built
by every app that has the layer, on every platform its name allows: each app's
project file takes its layers' folders by pattern (THE BUILDS, below).

THE TESTS: tests/run.sh (macOS or Linux; RDE beside the project, or RDE=...)
builds every suite with AddressSanitizer and UBSan and runs it; tests/README.md
has what each covers.

THE STRINGS: every text the app shows, in its five languages, is in the layers'
strings files — fude/drawing/strings.py (the core's), fude/study/strings.py (a
study app's), fude/lang/<code>/strings.py (its language's), fude/zoom/strings.py
(a canvas app's) — and the app's own (apps/<app>/tools/strings.py, when it has
any). python3 tools/strings/build.py kana writes apps/kana/assets/text/
strings.rdel and apps/kana/src/text_ids.h (don't edit those by hand); a layer's
string changed: python3 tools/strings/build.py all, every app at once.
THE FOURTH LANGUAGE is the one the app teaches (a learner may use the app in it):
Kana's Japanese; Hanzi's Chinese and Hangul's Korean, read from files beside each
layer's (fude/drawing/strings_zh.py, fude/study/strings_zh.py, fude/lang/zh/
strings_zh.py, apps/hanzi/tools/strings_zh.py; _ko for Hangul) of rows
x('ID', text). It takes Japanese's place only when every string has one (the tool
prints how many are missing), and the app then offers it with its flag
(assets/flags/cn.png, kr.png: drawn by tools/icons/flags.swift); until then those
apps keep Japanese. On the very first launch the app speaks the device's language
if it is one of its five, English otherwise.

THE BUILDS: every app is built by RDE's builder from its project file,
apps/<app>/<app>.rdeproj (its sources, flags, assets, frameworks, packaging, on
every platform; the format: ~/RDE/docs/docs/project_files.md), through one
script, which first does what a project file cannot say (the version, from the
app's src/version.h; InfiNote's and InfiniWorkshop's assets, put together; the
whisper.cpp libraries when missing; iOS signing from the environment):

  zsh tools/build/app.sh <app> [command] [profile] [builder options] [-- the app's arguments]

  zsh tools/build/app.sh kana                   # the Mac's debug build (the default profile)
  zsh tools/build/app.sh kana release           # the Mac's release (it takes no launch arguments)
  zsh tools/build/app.sh kana measure           # a release that takes them, to measure it: build/kana-measure/
  zsh tools/build/app.sh kana android           # the release APK: build/kana-android/game.apk
  zsh tools/build/app.sh kana install android   # ...installed on the tablet with adb and started (--device=SERIAL)
  zsh tools/build/app.sh kana bundle            # Google Play's App Bundle: build/kana-android/game.aab
  zsh tools/build/app.sh kana ios               # the iPad's, signed: build/kana-ios/Kana.ipa
  zsh tools/build/app.sh kana install ios       # ...installed on the iPad and started
  zsh tools/build/app.sh kana sim               # the Simulator's: build/kana-simulator/Kana.ipa
  zsh tools/build/app.sh kana run sim           # ...installed on the booted Simulator and started
  zsh tools/build/app.sh kana show android      # every setting of a profile, where it came from, its command

Every app has these profiles (Draw: the first three). docs/architecture.md, "The
builds", says why each line of a project file is there. --logcat after install
keeps the app's log streaming; --verbose prints every command the builder runs.
To bump the version, edit the app's src/version.h only.

The ENGINE needs no step of its own: a build checks the engine library it links
and rebuilds it first, for its platform, when it is missing or older than the
engine's sources (an engine change, or shaders.h made for another platform). So
the first build for a platform after another's takes some minutes longer. ONE
BUILD AT A TIME: every platform's engine build writes the same files in ~/RDE
(engine/src/shaders.h and the shaders' intermediate files), so two builds that
both rebuild an engine break each other (2026-10-15: one failed to compile, the
other crashed). tools/check/build_all.sh builds one after another.

ANDROID — the real test
-----------------------
On Windows (no zsh, so the version from the app's src/version.h by hand):

  cd C:\Users\borja\Programming\Projects\kana
  C:/Users/borja/Programming/RDE/builder.exe android --file=apps/kana/kana.rdeproj --version=0.5.4

(The SDK is found in %LOCALAPPDATA%\Android\Sdk, or ANDROID_HOME; the newest NDK in
it, or ANDROID_NDK_HOME. The engine for Android is built first when missing or old.)

The Android services are the apps' own Java (fude/android/java, com.rde.fude:
[android] java), reached from C through JNI (fude/drawing/base/android.h and the
*_android.c sources). Google's ML Kit comes from Maven, pinned by the app's
deps.lock (THE LIBRARIES, below) and downloaded once into build/android_deps.
Each app's [android] section has its permissions and why.


ANDROID (from the Mac) — tools/build/app.sh <app> android
-------------------------------------------------------
  zsh tools/build/app.sh kana android            # build/kana-android/game.apk, release
  zsh tools/build/app.sh kana install android    # built, installed on the tablet (USB, developer
                                                 # options on) and started; --logcat keeps its log
  zsh tools/build/app.sh kana bundle             # and Google Play's build/kana-android/game.aab

The APK is a release build: a low-end tablet (Galaxy Tab S6 Lite) is slow with a
debug build and smooth with a release one, so speed is judged on release. Its
version (versionName, and versionCode = major x 10000 + minor x 100 + patch, so
Kana 0.5.4 is 504) is the app's src/version.h's: Android refuses to install a
lower code over a higher one, and Play wants each upload higher.

GPUs: SDL's Vulkan asks by default for features some Android GPUs lack (the Tab S6
Lite's Mali-G72: depth clamping, clip distances, anisotropy) and refuses the
device; RDE then makes it again without them (logged: "GPU device made without
the optional features"). Nothing to do here; it is in the engine. A device with
no Vulkan at all cannot run RDE: the manifest requires Vulkan (Play hides the app
there), and a hand-installed APK shows "Graphics not supported" and closes.

Needs Android Studio (its JDK, the SDK at ~/Library/Android/sdk with platform and
build-tools 37 and an NDK). The builder finds the SDK (ANDROID_HOME says
otherwise) and uses its newest NDK (ANDROID_NDK_HOME says otherwise); it prints
both. app.sh gives it Android Studio's JDK, through build/jdk, a link without the
space Android Studio's path has.

THE SIGNING KEY: apps/<app>/android_signing/com.rde.<app>.keystore (alias and
passwords: the builder's, "android"), where the builder keeps it; that folder
ignores itself in git. The first build with the project files copied each from
build/<app>-android/, where the old builds kept them. Copies are in
~/kana-android-keys/ (never commit them): an APK signed with another key cannot
update the installed app, and Play needs the same key for every update.

THE LIBRARIES (ML Kit): apps/<app>/platform/android/deps.lock pins every Maven
artifact; the build reads it (the project file's dependencies_lock) and downloads
what is missing into build/android_deps (dependency_cache). The project files list
no dependencies of their own, so the builder never resolves the lock again by
itself (it would drop the PDFBox lines added by hand). To change a version,
resolve again, EVERY ROOT IN ONE COMMAND (separate runs would each pin their own
tree):

  ~/RDE/builder --android_dep_cache=build/android_deps \
    --android_dep_resolve=com.google.mlkit:digital-ink-recognition:19.0.0 \
    --android_dep_resolve=com.google.mlkit:translate:17.0.3 \
    --android_dep_resolve=com.google.mlkit:text-recognition-japanese:16.0.1 \
    --android_dep_resolve=com.google.android.gms:play-services-mlkit-document-scanner:16.0.0 \
    --android_deps_out=apps/kana/platform/android/deps.lock

(text-recognition-chinese for Hanzi, -korean for Hangul, -devanagari for Hindi;
Thai and Arabic: text-recognition, the Latin one, only for FudeText.java to build.
The canvas apps resolve only digital-ink-recognition and the document scanner.)
Then add back by hand the PDFBox lines at the end of the old lock
(com.tom-roush:pdfbox-android, without the BouncyCastle it would resolve to).
The libraries' native code (jni/<abi>) and model files (assets/) go into the APK
with them, and their manifests are merged.

THE EMULATOR (no tablet at hand): an AVD (Device Manager in Android Studio), then
  zsh tools/build/app.sh kana install android --logcat     # or by hand:
  adb install -r build/kana-android/game.apk
  adb shell am start -n com.rde.kana/.KanaActivity
  adb logcat | grep -E "SDL_RDE|Fude"
Its GPU is software: ~20 frames a second, and a quick tap can begin and end
between two frames — hold taps (adb shell input swipe x y x y 200).

On Android the window is laid out in dp (rde_window_set_density_scaling, called
by fude_app_window), as iOS in points: an iPad's sizes on an Android tablet.

Android's Back (button or gesture; Escape on a computer) closes what is on top as
its own button would (fude_app_back): Settings' cards, Settings, the side panel,
the toolbar's palettes, the page's menu, then the screen on top through its row's
Back or Close; the document bar's search; a lasso selection. With nothing open it
is the system's Back (rde_mobile_system_back): the app goes to the background.


iOS (from the Mac) — the iPad
-----------------------------
  cd ~/kana
  FUDE_IOS_PROFILE="<the com.rde.kana .mobileprovision>" zsh tools/build/app.sh kana ios
  FUDE_IOS_PROFILE="<the com.rde.kana .mobileprovision>" zsh tools/build/app.sh kana install ios

The first builds build/kana-ios/Kana.ipa (release, signed); the second also
installs it on the connected iPad and starts it (--device=<UDID> when several
are connected, --logcat to keep its console). The project file's [ios] section
and [profile ios] hold the rest: the system frameworks, ML Kit's and the
language's text recognition model, the bundles. The signing identity is the one
Apple Development identity in the keychain; with several, also
FUDE_APPLE_TEAM="vazquezborja@hotmail.es (7VRZRRF73U)" (without the "Apple
Development: " prefix).

apps/kana/platform/ios/ holds what the app is on iOS besides its code: the asset catalog
(Assets.xcassets: the icon, AppIcon-1024.png, drawn from AppIcon.svg — 日本語 in
KanjiVG's strokes before a red sun, over an open book; LaunchIcon, the icon
rounded as iOS rounds it, for the launch screen; LaunchBackground, the launch
screen's colour: Paper's page, Night's in dark mode), the launch screen (LaunchScreen.storyboard:
the icon centred, 160 points) and Kana's
own Info.plist keys (Info.plist: iPad only, portrait either way up — the app locks it on Android too, app.c — full screen, no
non-exempt encryption, the camera's purpose, Kana's five languages), merged over
the engine template's; localized/<language>.lproj/InfoPlist.strings, the camera
prompt in each language, go into the app through [ios] bundles (a plain folder:
its contents are copied beside the executable) — and make the App Store list the
five languages. [ios] asset_catalog, launch_storyboard and plist name the rest;
without them a build gets the template's.

ML Kit (Google's handwriting recognition, used by Check and Copy as text; and
its text recognition with the Japanese model, used by Text from photo) must be
set up ONCE before the first iOS build — and again after the tool changes — it
downloads the pinned pods and builds their sources into third_party/mlkit/
(git-ignored), no CocoaPods needed:

  python3 tools/mlkit/setup.py

[profile ios]'s frameworks, bundles, include and link_flags are ML Kit's. The
Japanese model (~20 MB) downloads on the app's first run.

The package name (com.rde.kana) must match the provisioning profile's app id. The
profile is a free-team one and EXPIRES AFTER 7 DAYS: regenerate it in Xcode with
the iPad connected, then point FUDE_IOS_PROFILE at the new file.

Install and launch by hand (devicectl installs the .app, not the .ipa):

  unzip -o build/kana-ios/Kana.ipa -d /tmp/kana_ipa
  xcrun devicectl device install app --device <UDID> /tmp/kana_ipa/Payload/Kana.app
  xcrun devicectl device process launch --device <UDID> --terminate-existing com.rde.kana

`xcrun devicectl list devices` shows the UDID. First launch on a device needs
Settings > General > VPN & Device Management > trust the developer.

A RELEASE BUILD TAKES NO ARGUMENTS: whatever it is launched with is ignored, by
Kana and by RDE — users cannot change how it behaves. Debug builds read them
(the look flags below, --perf, the bake). To measure a release on the Mac, build
the measure profile (zsh tools/build/app.sh kana measure: FUDE_ALLOW_ARGS, its own
folder). On the iPad: zsh tools/build/app.sh kana ios -DFUDE_ALLOW_ARGS (the
option is added to the profile's), into build/kana-ios/ — build it again without
before shipping.

Measuring a build on the device (the iPad unlocked): launch it on a screen
with --perf=SECONDS — frame times are appended to perf.txt in its save folder,
then copied back (--browse, --chart, --album, --stats, --exam: those screens;
no screen flag: the page):

  xcrun devicectl device process launch --device <UDID> --terminate-existing com.rde.kana --browse --perf=8
  xcrun devicectl device copy from --device <UDID> --domain-type appDataContainer --domain-identifier com.rde.kana \
      --user mobile --source "Library/Application Support/rde/engine/kana/perf.txt" --destination perf.txt

The release build on the iPad mini 6, 2026-10-01: every screen 59.9 fps, Kana's
render 1.5-5.4 ms a frame.


iOS SIMULATOR (from the Mac) — the App Store's screenshots, any iPad
-------------------------------------------------------------------
Xcode's Simulator draws an iPad at its real size: the iPad Pro 12.9-inch (6th
generation) gives 2048 x 2732, the size App Store Connect takes for the 13-inch
iPad. The builder's --ios_simulator builds for it instead of a device (its own
build/.../ios_simulator/ folders; signed ad hoc, no profile), and the code tells
it apart by RDE_PLATFORM_IOS_SIMULATOR (rde.h; RDE_PLATFORM_IOS too). ML Kit has
no Simulator build: mlkit, textscan and translate use their stand-ins there
(no Check by ML Kit, no text from photos, no translations; the camera is none).

The app, debug (it reads the look flags):

  zsh tools/build/app.sh kana sim            # build/kana-simulator/Kana.ipa
  zsh tools/build/app.sh kana run sim        # ...installed on the booted Simulator and started
                                             # (-- --stay --viewer=65E5: the app's arguments)

It goes to build/kana-simulator/ (its own: the packager writes Kana.ipa at the
output folder's top, and would replace the device's), signed ad hoc, and without
ML Kit, but with the system's PhotosUI, ImageIO, VisionKit, PDFKit and CoreText
(Lectures: From Photos, pictures made into a PDF, Scan pages; a PDF's text).

A Simulator of the iPad, installed and launched by hand (simctl installs the .app):

  xcrun simctl create "Kana iPad 12.9" com.apple.CoreSimulator.SimDeviceType.iPad-Pro-12-9-inch-6th-generation-8GB com.apple.CoreSimulator.SimRuntime.iOS-17-4
  xcrun simctl boot <UDID>                                    # the UDID create printed
  unzip -o build/kana-simulator/Kana.ipa -d /tmp/kana_sim
  xcrun simctl install <UDID> /tmp/kana_sim/Payload/Kana.app
  xcrun simctl status_bar <UDID> override --time "9:41" --batteryState charged --batteryLevel 100 --wifiBars 3
  xcrun simctl launch <UDID> com.rde.kana --stay --viewer=65E5
  xcrun simctl io <UDID> screenshot shot.png                  # some seconds later: 2048 x 2732

open -a Simulator shows it (a mouse or trackpad writes as a finger does). The
app's saves are in xcrun simctl get_app_container <UDID> com.rde.kana data, under
Library/Application Support/rde/engine/kana/ — planted data goes there before a
launch. --stay runs a look's sequence (--press, --paste-text...) as --shot does,
without the shot and without quitting: the Simulator's screenshot is taken from
outside. apps/kana/tools/store/screenshots.py then frames and captions them.

The store's shots, per language (N: its place in Kana's languages, en 0 es 1 pt
2 ja 3 fr 4): the saves emptied, then

  xcrun simctl launch <UDID> com.rde.kana --stay --demo=es --language=1    # once: the demo, in Spanish (it saves itself)
  xcrun simctl launch <UDID> com.rde.kana --stay --translate-demo --vocab=1  # then each screen, a screenshot each
      (--viewer=8A9E, --word-exam=1, --viewer=65E5, --stats, --album, --album-page=65E5)

keeping a copy of the demo's saves to put back before each shot.

--note=TEXT (with --viewer=HEX) that character's note set to TEXT; --vocab[=N] the
Vocabulary screen (on the Nth list; --vocab-search=WORDS: what its field finds),
--vocab-sample a few words and a list first (when there are none),
--word-exam[=STAGE] a word exam of every word (0 setup, 1 writing, 2 by ear, 3

--word-translate=MEANING the word card with MEANING translated into Japanese (made

--scan-live the live
camera, for measuring on the device), --trim-fonts (the fonts trimmed as on going to the background, just
before the shot: every glyph drawn again from nothing), its size and theme (--size=744x1133 is an iPad
mini's points, --theme=N), how far down (--scroll=PX), and --shot=FILE: a PNG
of the window once it has settled, then the app quits (--stay: the same without
the shot or quitting, for a screenshot from outside — the Simulator's). --press=I,J,... presses
the buttons of the row of the screen on top in turn, as taps would (from frame
30, one every four frames; the shot waits for the last), and --language=N
switches to Kana's Nth language at frame 12 — to check what the buttons DO.
--demo[=LANG] fills empty saves with six weeks of a learner's work, written and
scored by the app itself (fude/study/app/demo.c: practice, exams, marks, reviews,
a vocabulary in four lists, notes; LANG en es pt ja fr for the meanings, the
lists' names and the notes), for the store's screenshots. --translator=TEXT[|TEXT]
opens Into Japanese with those asked, and --translate-demo makes Translate with
Google's buttons show: both with made-up translations, the desktop's and the
Simulator's (no ML Kit). All of it
without a device (fude/drawing/app/look.h has the core's flags, fude/study/app/
look.c a study app's, among them --chart, --welcome[=PAGE], --offline-note,
--library). Documents (fude/drawing/doc/): --doc=PDF a new canvas over a copy of
that PDF, opened; --book=N the app's Nth lecture opened (its canvas, made the
first time); --doc-view=ZOOM,X,Y the view at frame 20 (X, Y: the canvas point in
the middle of the screen; the first page's top is at 0, pages go down) — a shot
with a document waits until frame 100, its pages drawn by then. --mark=X0,Y0,X1,Y1[;...]
marker strokes; --lasso-area=X0,Y0,X1,Y1 a lasso loop round that box (on a
PDF's text: the text row); --doc-search=WORDS the document bar's Search;
--doc-page=N its page N (all canvas units, at frames 22-26); --doc-turn=N its
page N turned a quarter clockwise (frame 30); --doc-export=PDF
the document written there with its ink (frame 90); --read-demo the pages
without text "read" into made-up lines (no ML Kit on the desktop).

A phone (fude_kit_compact, kit.h: the screen's shorter side under 600 points/dp)
gets the same UI laid out tighter: a row's buttons that do not fit go under More
(a menu over the row; Back closes it), the filter chips scroll sideways with
icon-only toggles, the search field takes a line of its own, the welcome card's
words get smaller, and Settings puts a setting's name over its choices and
scrolls (--scroll=PX scrolls it too). Looked at on the Mac with --size=411x880 (a
Galaxy S23), 360x640, 393x852 (an iPhone 15) or 375x667 (an iPhone SE).
And everything is smaller there: Settings' Interface size (Small, Medium, Large:
a window unit at 0.8, 1, 1.15 of a point/dp — RDE's rde_window_set_ui_scale) is
Small on a phone until one is chosen, Medium on anything bigger (app.h,
FUDE_UI_SIZE_). --size is the device's size in points, the scale on top;
--ui-size=N looks at another (1 Small, 2 Medium, 3 Large, 0 the device's).
--voice-card[=android] shows the voice card (how to add a voice: the iPhone and
iPad's steps, or Android's with Open settings); --voice-missing makes a
computer's voice count as missing (the side panel's Set up the voice, and the
card once after the offline one); --note-card=folder|canvas|rename adds a note
and opens its card at frame 15 (it changes the saves: use scratch ones).

On the device (a build that takes arguments, as for --perf):
--translate-probe=xx tries ML Kit's translator — Japanese into xx (en, es, pt,
fr), its models downloaded when missing, four sentences — and writes the answers
and times to translate.txt in the save folder (copy it back as perf.txt is). The
app carries on afterwards: an iOS app cannot quit itself.

  ./build/kana/osx-silicon/debug/project/exe/runnable --size=744x1133 --stats --scroll=900 --shot=/tmp/stats.png

Saves are ./saves/ under the folder it runs in: run it from another folder
(with links to runnable, libRDE.dylib and assets) to look at planted data.


DRAW (the drawing app) — on the Mac
----------------------------------
The drawing core alone (fude/drawing), no study layer: an endless page, the
toolbar, the side panel's canvases, Settings. Its sources are its shell and the
core's — every file of fude/drawing/ (apps/draw/draw.rdeproj: the computer's
builds only, as it is not released):

  cd ~/kana

THE CHARACTER DATA BAKE
-----------------------
apps/kana/assets/data/characters.kana is BAKED from KanjiVG + KANJIDIC2, with the
JLPT lists, JMdict's example words and Tatoeba's example sentences (format in
fude/study/chars/kanji.h; the bake: fude/lang/ja/bake.c). Re-bake only when the sources are updated. The sources are
not in the repository (data/raw/ is ignored):

  mkdir -p data/raw && cd data/raw
  curl -L -o kanjivg.xml.gz https://github.com/KanjiVG/kanjivg/releases/download/r20250816/kanjivg-20250816.xml.gz
  curl -L -o kanjidic2.xml.gz http://www.edrdg.org/kanjidic/kanjidic2.xml.gz
  curl -L -o JMdict.gz http://ftp.edrdg.org/pub/Nihongo/JMdict.gz
  curl -L -o JMdict_e.gz http://ftp.edrdg.org/pub/Nihongo/JMdict_e.gz
  gunzip -k kanjivg.xml.gz kanjidic2.xml.gz
  gunzip -c JMdict.gz > JMdict.xml
  gunzip -c JMdict_e.gz > JMdict_e.xml
  mkdir -p jlpt
  for n in 1 2 3 4 5; do
    curl -L -o jlpt/n$n-kanji-char-eng.mem http://www.tanos.co.uk/jlpt/jlpt$n/kanji/n$n-kanji-char-eng.mem
  done
  mkdir -p tatoeba && cd tatoeba
  for l in jpn eng spa fra por; do
    curl -L https://downloads.tatoeba.org/exports/per_language/$l/${l}_sentences.tsv.bz2 | bunzip2 > ${l}_sentences.tsv
  done
  for p in jpn-eng jpn-spa jpn-fra jpn-por; do
    curl -L https://downloads.tatoeba.org/exports/per_language/jpn/${p}_links.tsv.bz2 | bunzip2 > ${p}_links.tsv
  done
  curl -L https://downloads.tatoeba.org/exports/jpn_indices.tar.bz2 | tar xj
  cd ../../..

(The JLPT files are Jonathan Waller's N5-N1 kanji lists as Mnemosyne decks,
CC BY; the bake reads the kanji out of them. JMdict is EDRDG's Japanese
dictionary, CC BY-SA 4.0 like KANJIDIC2; the bake keeps up to twenty words a
kanji (six of them its examples). The FULL JMdict (JMdict.xml) is what the bake
reads when it is there: its English, and the Spanish and French glosses for
the other languages (it has no Portuguese: those words stay English). Without
it, JMdict_e (English only) — then the words have no other languages. Kanji
meanings in Spanish, Portuguese and French come from KANJIDIC2. JMdict is
updated daily: a re-bake picks up whatever the download has. Tatoeba's
sentences are CC BY 2.0 FR: the bake keeps one per word — a Japanese sentence
of a comfortable length with the word in it and an English translation, and
the Spanish, French and Portuguese ones when Tatoeba has them; ~1.6 MB.
jpn_indices.csv, Tatoeba's word index, says which word a sentence has (行 read
ぎょう or the 行 of 行く): without it the words are found as text, more loosely. The
English file is large (~110 MB): the bake reads it whole, outside RDE's memory
pool. Without data/raw/tatoeba/ the file has no sentences and the viewer shows
none.)

Then, with the Mac desktop build above, from the project root:

  ./build/kana/osx-silicon/debug/project/exe/runnable --bake
      [--kanjivg=PATH] [--kanjidic=PATH] [--jlpt=DIR] [--jmdict=PATH] [--tatoeba=DIR] [--out=PATH]

It reports characters, strokes, sizes, stroke-count disagreements and example
words and sentences, then the look-alikes (the matcher over the file just
written, appended as 'LOOK': ~18 s), and takes about twenty-five seconds. The sources are CC BY-SA and CC BY: apps/kana/assets/data/LICENSE-data.txt must
ship with the app and its attribution must be shown to users.

A bake is deterministic: the same sources give the same bytes. So a change to the
bake's code (study/chars/bake.c, lang/*/bake.c) is checked by baking every
language before and after it and comparing the files (cmp): they must be
identical unless the change means to alter the data. (Done for the move of the
bake onto RDE's arrays and map, 0.5.4: all seven files identical.)

WHAT TO LOOK FOR ON THE DEVICE
------------------------------
1. The top line of the HUD. "PEN" means stylus events arrive and the shared-ink
   plan holds. "TOUCH ONLY" on an iPad with an Apple Pencil is the answer to
   open question 1 in apps/kana/docs/design.md, and it is a bad one.

2. Pressure moving as you press harder, and the stroke visibly thickening. If
   pressure stays 0.00 the PEN_AXIS events are not arriving even though position
   is — a different failure from no pen at all, and worth knowing apart.

3. INPUT HZ while drawing continuously. A pen sampling at 120-240 Hz that shows
   ~60 here is being coalesced to the frame rate: fast strokes will come out as
   visible polygons however low the lag is. Press M and draw fast — evenly
   spaced dots mean the full rate is arriving, long gaps on the quick parts mean
   it is not.

4. THE GAP. Press H to hide the HUD, draw a fast circle, and look at the
   distance between the nib and the end of the ink. That distance IS the latency
   and it is the only honest measure of it — the numbers on screen cover the
   app's half only, because everything before the event reaches the process is
   invisible from inside it. Photograph it if you want a number: gap in mm,
   divided by pen speed in mm/ms.


THE APP STORE
-------------
apps/kana/docs/app_store.md: what leaves the device, the permissions, the
privacy manifests, App Store Connect's App Privacy answers, what is still open.
apps/kana/store/: listing.md, the store texts in the five languages, the age
rating, the review notes; README.md, the screenshots (screenshots/, framed/) and
how to swap one.

  python3 tools/store/site.py [app...]                      # every app's help + privacy pages: apps/<app>/site/
  python3 tools/store/site.py --pages DIR                   # ...and DIR/<app>/ for the GitHub Pages repository
  python3 -m pip install pillow                             # once, for the next
  python3 apps/kana/tools/store/screenshots.py SHOTS [OUT]  # iPad screenshots -> 13-inch, captioned, per language
  python3 apps/kana/tools/store/screenshots.py apps/kana/store/screenshots apps/kana/store/framed
