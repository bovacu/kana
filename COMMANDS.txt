kana — build commands
=====================

The engine is built separately from the app, and it is built PER PLATFORM. A
Windows engine build followed by an Android app build (or the reverse) does not
work: rde_config.h and shaders.h are regenerated per platform. Build the engine
for the platform you are about to target, first.


DESKTOP (Windows) — for developing the ink without a tablet in hand
-------------------------------------------------------------------
Left-click drags as a stand-in for the pen. It CANNOT answer the questions the
spike exists for — no pressure, no tilt, and desktop latency says nothing about
a tablet's. Use it to iterate on the code, then measure on a device.

  cd C:\Users\borja\Programming\RDE
  builder.exe --engine --debug

  cd C:\Users\borja\Programming\Projects\kana
  C:/Users/borja/Programming/RDE/builder.exe --project --debug ^
    --assets_path=C:/Users/borja/Programming/Projects/kana/assets/ ^
    --output_path=C:/Users/borja/Programming/Projects/kana/build/ ^
    kana.c src/ink.c src/canvas.c src/toolbar.c src/save.c src/lasso.c src/kfile.c src/kanji.c src/bake.c src/viewer.c src/glyph.c src/catalog.c src/match.c src/browse.c src/scroll.c src/chart.c src/score.c src/history.c src/practice.c src/theme.c src/album.c -IC:/Users/borja/Programming/Projects/kana/include ^
    -Werror -Wall -Wextra

  build\windows\debug\project\exe\runnable.exe


ANDROID — the real test
-----------------------

old .so, and the change simply is not in the APK.

  cd C:\Users\borja\Programming\RDE
  builder.exe --engine --debug --android --abi_armv8a ^
    --android_ndk=C:\Users\borja\AppData\Local\Android\Sdk\ndk\30.0.15729638\ ^
    --android_sdk=C:\Users\borja\AppData\Local\Android\Sdk\ ^
    --android_api_level=37

  cd C:\Users\borja\Programming\Projects\kana
  C:/Users/borja/Programming/RDE/builder.exe --project --debug --android ^
    --android_app_name=Kana --android_package_name=com.rde.kana ^
    --assets_path=./assets/ --abi_armv8a ^
    --android_ndk=C:\Users\borja\AppData\Local\Android\Sdk\ndk\30.0.15729638\ ^
    --android_sdk=C:\Users\borja\AppData\Local\Android\Sdk\ ^

No --android_internet: the spike talks to nothing. Add it only when something
actually needs the network, and never by default.


iOS (from the Mac) — the iPad
-----------------------------
ENGINE FIRST, same rule as Android. Run the builder from the project root; the
paths are absolute on purpose.

  cd ~/RDE
  ./builder --engine --ios --debug

  cd ~/kana
  ~/RDE/builder --project --debug --ios \
    --assets_path=/Users/borjavazquez/kana/assets/ \
    --output_path=/Users/borjavazquez/kana/build/ \
    --ios_package_name=com.rde.kana --ios_app_name=Kana \
    "--apple_development_name=vazquezborja@hotmail.es (7VRZRRF73U)" \
    "--ios_provisioning_profile=<~/Library/MobileDevice/Provisioning Profiles/....mobileprovision>" \
    kana.c src/ink.c src/canvas.c src/toolbar.c src/save.c src/lasso.c src/kfile.c src/kanji.c src/bake.c src/viewer.c src/glyph.c src/catalog.c src/match.c src/browse.c src/scroll.c src/chart.c src/score.c src/history.c src/practice.c src/theme.c src/album.c -I/Users/borjavazquez/kana/include -Wall -Wextra

--apple_development_name WITHOUT the "Apple Development: " prefix — the builder
adds it. --ios_package_name must match the profile's app id (com.rde.kana). The
profile is a free-team one and EXPIRES AFTER 7 DAYS: regenerate it in Xcode with
the iPad connected, then point the command at the new file.

Install and launch (devicectl installs the .app, not the .ipa):

  unzip -o build/Kana.ipa -d /tmp/kana_ipa
  xcrun devicectl device install app --device <UDID> /tmp/kana_ipa/Payload/Kana.app
  xcrun devicectl device process launch --device <UDID> --terminate-existing com.rde.kana

`xcrun devicectl list devices` shows the UDID. First launch on a device needs
Settings > General > VPN & Device Management > trust the developer.

If the builder was just rebuilt (rde_build.c changed), the FIRST run can fail on
the name's spaces/parentheses — it re-runs itself unquoted. Run it again.

THE CHARACTER DATA BAKE
-----------------------
assets/data/characters.kana is BAKED from KanjiVG + KANJIDIC2 (format in
include/kanji.h). Re-bake only when the sources are updated. The sources are
not in the repository (data/raw/ is ignored):

  mkdir -p data/raw && cd data/raw
  curl -L -o kanjivg.xml.gz https://github.com/KanjiVG/kanjivg/releases/download/r20250816/kanjivg-20250816.xml.gz
  curl -L -o kanjidic2.xml.gz http://www.edrdg.org/kanjidic/kanjidic2.xml.gz
  gunzip -k kanjivg.xml.gz kanjidic2.xml.gz
  mkdir -p jlpt
  for n in 1 2 3 4 5; do
    curl -L -o jlpt/n$n-kanji-char-eng.mem http://www.tanos.co.uk/jlpt/jlpt$n/kanji/n$n-kanji-char-eng.mem
  done
  cd ../..

(The JLPT files are Jonathan Waller's N5-N1 kanji lists as Mnemosyne decks,
CC BY; the bake reads the kanji out of them.)

Then, with the Mac desktop build above, from the project root:

  ./build/osx-silicon/debug/project/exe/runnable --bake
      [--kanjivg=PATH] [--kanjidic=PATH] [--jlpt=DIR] [--out=PATH]

It reports characters, strokes, sizes and stroke-count disagreements, and takes
about a second. The sources are CC BY-SA and CC BY: assets/data/LICENSE-data.txt must
ship with the app and its attribution must be shown to users.


WHAT TO LOOK FOR ON THE DEVICE
------------------------------
1. The top line of the HUD. "PEN" means stylus events arrive and the shared-ink
   plan holds. "TOUCH ONLY" on an iPad with an Apple Pencil is the answer to
   open question 1 in docs/design.md, and it is a bad one.

2. Pressure moving as you press harder, and the stroke visibly thickening. If
   pressure stays 0.00 the PEN_AXIS events are not arriving even though position
   is — a different failure from no pen at all, and worth knowing apart.

3. INPUT HZ while drawing continuously. A pen sampling at 120-240 Hz that shows
   ~60 here is being coalesced to the frame rate: fast strokes will come out as
   visible polygons however low the lag is. Press M and draw fast — evenly
   spaced dots mean the full rate is arriving, long gaps on the quick parts mean
   it is not.

4. THE GAP. Press H to hide the HUD, draw a fast circle, and look at the
   distance between the nib and the end of the ink. That distance IS the latency
   and it is the only honest measure of it — the numbers on screen cover the
   app's half only, because everything before the event reaches the process is
   invisible from inside it. Photograph it if you want a number: gap in mm,
   divided by pen speed in mm/ms.
